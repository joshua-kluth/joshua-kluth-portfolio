Autonomous Drone Navigation System

Vision-based obstacle avoidance for quadcopter UAVs

Type University Project
Role Lead Designer & Developer
Tools Python, OpenCV, ROS, MATLAB, Simulink
Duration September 2023 – May 2024

Overview

This project involved designing and implementing an autonomous navigation system for a quadcopter drone capable of real-time obstacle detection and avoidance in unknown environments. The system integrates computer vision algorithms with classical control theory to enable safe autonomous flight through complex indoor and outdoor spaces.

Context & Problem

Traditional drone navigation systems rely heavily on GPS and pre-mapped environments, limiting their usefulness in GPS-denied areas and dynamic environments. The goal was to develop a vision-based system that could operate autonomously without prior environmental knowledge.

Key Challenges & Constraints

  • Real-time performance: Vision processing must run at minimum 20 Hz for safe navigation
  • Limited computational resources: All processing must run on embedded hardware (Raspberry Pi 4)
  • Weight constraints: Total payload limited to 200g including camera and compute
  • Robust detection: System must handle varying lighting conditions and environments
  • Safety requirements: Guaranteed obstacle detection within 2-meter range
  • Battery life: Maintain at least 15 minutes of flight time with full system active

Key Design Decisions

  • Monocular vision approach: Used single forward-facing camera with depth estimation via optical flow to minimize weight and computational complexity
  • Hierarchical control: Separated high-level path planning from low-level attitude control for modularity and easier tuning
  • PID cascade controller: Implemented nested PID loops for position and attitude control, providing stability while maintaining computational efficiency
  • ROS middleware: Leveraged Robot Operating System for inter-process communication and sensor fusion

Vision Processing Pipeline

The computer vision system processes camera frames through the following stages:

  1. Image acquisition and preprocessing (grayscale conversion, histogram equalization)
  2. Feature extraction using ORB (Oriented FAST and Rotated BRIEF) descriptors
  3. Optical flow computation to estimate depth and relative motion
  4. Obstacle segmentation using adaptive thresholding
  5. Potential field generation for collision avoidance

Obstacle Detection Algorithm

Obstacles are detected by analyzing the optical flow field. Dense regions of flow vectors indicate nearby objects. The relative depth is estimated using the inverse of flow magnitude:

Depth estimation: Z ≈ k × f / ||v||

Where Z is depth, f is focal length, ||v|| is flow magnitude, and k is a calibration constant.

Performance Optimization

To achieve real-time performance on embedded hardware, several optimizations were implemented:

  • Reduced image resolution to 640×480 for processing (maintained 1080p logging)
  • Used multi-threading to parallelize vision and control tasks
  • Implemented sparse optical flow (Lucas-Kanade) instead of dense flow
  • Applied region-of-interest masking to ignore floor and sky

Key Outcomes

  • Successfully demonstrated autonomous navigation through obstacle course with 95% success rate across 50 test flights
  • Achieved real-time performance (23 Hz average) on embedded Raspberry Pi 4 hardware
  • Maintained stable flight with position hold accuracy within 15cm RMS error
  • System proved robust to varying lighting conditions (tested from 100 to 1000 lux)
  • Exceeded battery life requirement with 18-minute average flight duration

Project Impact

The system demonstrated that effective autonomous navigation can be achieved using lightweight, low-cost sensors and embedded computation. Results were presented at the university's annual engineering symposium and are being considered for publication. The modular software architecture has been adopted by the university's robotics lab for future UAV projects.

Reflection & Learnings

What I Learned

  • Systems integration is challenging: Getting hardware, vision algorithms, and control systems to work together reliably required careful debugging and system-level thinking
  • Real-time constraints matter: Theoretical algorithms often need significant optimization for embedded deployment
  • Testing is crucial: Extensive simulation in Gazebo caught many edge cases before expensive hardware testing
  • Documentation pays off: Maintaining detailed logs and documentation enabled rapid troubleshooting during integration
  • Control theory fundamentals: Deepened understanding of PID tuning, stability analysis, and practical controller implementation

Future Improvements

  • Implement SLAM (Simultaneous Localization and Mapping) for better long-term navigation and path planning
  • Upgrade to stereo vision for more accurate depth estimation
  • Explore model predictive control (MPC) for more optimal trajectory planning
  • Add machine learning-based object recognition to distinguish obstacle types
  • Improve robustness in outdoor environments with wind disturbance compensation
